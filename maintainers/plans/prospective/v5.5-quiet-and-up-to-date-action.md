## S1 — An engine skill on a long-lived brain comes up to date again _(#115)_

**What the person using Kenjaku lives today.** On a brain that has crossed several releases, `/lint`,
`/consolidate` and their siblings **stop receiving updates for good**. The new version lands beside the
old one as `SKILL.md.new`, so nothing is lost and nothing is silent — but the report explains it with a
sentence that is not true: *"your customized lint skill was kept exactly as you wrote it"*, about a file
they have never opened. From then on every release arrives as homework.

**What they would live instead.** The skill simply comes up to date, the way it does on a brain
installed fresh, and the word *customized* is kept for files they really did edit.

### Why it happens, in one paragraph — and why HEAD's own tests cannot see it

A staged skill (`engine-skills/<name>/`, delivered into `.claude/skills/<name>/`) has **no recorded
provenance**. Its stand-in is the brain's **own** `engine-skills/` copy, read at update time
(`readStagedProvenance`, `scripts/lib/staged-skills.mjs`) — the question being *"is what is installed
still what we delivered?"*. That works while the two move together. An update that advances the
**staging** copy without the **installed** one makes them disagree **permanently**: from that update on,
`mergeVerdict` reads the installed file as an owner edit (`owner-edit-stands`), then hands out a `.new`
sidecar at every release, for ever. The first divergence happens on the two-pass update out of an **old**
engine — the old-parent/new-child path no suite here can observe (`CONVENTIONS` §10ter), which is why
HEAD's code is correct in isolation and the fleet is still wrong.

### The fix this plan recommends, and the one it rejects

**Recommended: prove the installed skill against what the engine REALLY published, not against the
brain's own copy of it.** The machinery already exists and is already trusted for exactly this job:
`scripts/lib/engine-fingerprints.json` records, per published version, the bytes of every merge-regime
file, and `healFromDisk` / `healOne` (`scripts/lib/engine-heal.mjs`) turn **membership in that table**
into a provable `recorded` sha. Today the table is scoped by `selectMergeFiles`, so the staged skills are
outside it. Widen the scope, and a contaminated brain's installed skill is recognised as *a version we
shipped* → `refresh`, not *an owner edit*.

- 🛑 **The property that must survive: the proof is MEMBERSHIP, never arithmetic.** A sha may be recorded
  only because the installed bytes are **recognised** in the table, never computed from the installed
  bytes themselves. The day that slips, a real owner edit reads as untouched and the next update
  clobbers it. `engine-heal.mjs`'s own header says it; widening its input may not weaken it.
- **Rejected: record real provenance for staged skills at install time.** It is the tidier design and it
  **heals nobody** — a brain already diverged stays diverged, and diverged brains are the entire
  population this issue is about.

### The steps

- [x] **S1.1 — the table of what the engine really published grows to cover the staged skills.**
      _(2026-09-13)_ `selectFingerprintSources` now has **two doors**: the `merge` regime as before,
      and the **staging path** — `installedRelOf` maps `engine-skills/<name>/…` (and its
      `templates/<locale>/` twin) to `.claude/skills/<name>/…`, so the row is keyed by the
      **installed** path, like every other row.
  - **What it bought, measured**: the table went from 15 files / 104 byte-states to **24 / 129**, and
    the nine staged skills now carry their whole history — `lint` five states back to **v3.6.0**,
    `consolidate` six, `switch` eight. That reach is what makes the heal RETROACTIVE: whichever
    version a contaminated brain is stuck on, the bytes it holds are in a row.
  - **The tombstone gate applies to BOTH doors**, and that is why `rejectRetired` was extracted out of
    `selectMergeFiles` rather than respelled: a retirement is spelled at the installed path, so a
    retired skill may not be healed back into recognition through the newer door.
  - The generator (`maintainers/fingerprints/generate-fingerprints.mjs`) reads every published tag
    under **HEAD's** regime — that choice is deliberate and is exactly what makes a retroactive heal
    possible; do not make it ask each tag about itself.
  - The freshness guard stays green, and a **second, tree-anchored guard** joins it in
    `engine-fingerprints.test.mjs`: every staged skill this release ships must be placeable at the rel
    a brain installs it at. Narrow the selection back and it goes red naming the skills that lost
    their rows.
  - ⚠️ The table was regenerated at `--version v5.5.0` **as part of this step**, because the freshness
    guard goes red the moment the selection widens. **S1.4 still stands**: any later commit that
    changes a merge or staged file needs the run again, and it is owed once more at the tag.
- [x] **S1.2 — the refresh proves an installed skill against that table.** _(2026-09-13)_ The seam was
      the `recorded` **input** and nothing below it: `verifyBase`, `mergeVerdict` and the base plumbing
      are untouched. `proveStagedSkills` (`staged-skills.mjs`) reads the installed staged bytes and
      recognises them through `recogniseInstalled` — the proof `healProvenance` already ran on, shared
      rather than re-spelled. It layers **over** the staging stand-in: recognition is the stronger
      fact, and a rel nothing recognises falls back to the stand-in, which is what keeps a real edit
      preserved.
  - ✅ The red test that came first, and it was red: a brain whose `engine-skills/lint/SKILL.md` is at
    `1.1.0` while `.claude/skills/lint/SKILL.md` is at `1.0.0` comes out `refresh`, with no `.new`.
  - ✅ The companion pole, green throughout: a genuinely edited skill, whose bytes match **no**
    published version, is still preserved with its sidecar — **with the table present**, so the test
    proves the table cannot weaken it.
  - 🛑 **NOTHING PROVEN HERE IS PERSISTED, and that is load-bearing.** `reseedProvenance` advances
    merge files only, so a staged rel written into the manifest would freeze at the version it was
    proven at and then outrank the stand-in for ever — this very defect in mirror image. It is
    recomputed at each update instead (cheap), and a test asserts `healedProvenance` carries no staged
    rel. **Do not "tidy" this into the manifest.**
  - A **self-heal proves nothing**: all three refresh families stand down on `sourceDir === brainDir`,
    so reading the installed skills tree there would be work paid at every session start for nothing.
- [x] **S1.3 — the update report stops calling a file customized when nobody customized it.**
      _(2026-09-13)_ The guard is at the **product surface**: contaminated brain → reconcile →
      `formatReport`, and the rendered text must say *engine skill brought up to date: lint* and
      contain neither *customized* nor a `.new` path. Both halves together, because "the word is
      absent" passes just as well on a report that says nothing. **Verified to discriminate**: with
      the staged proof removed it goes red, and it was the only thing that caught it at the surface.
  - **The prose was re-read, and it needed no change — here is why, so nobody re-opens it.** After
    S1.1–S1.2 the sentence fires only when the installed bytes match **no version the engine ever

      `node maintainers/fingerprints/generate-fingerprints.mjs --version v5.5.0`. It is a per-release

  - 🔬 **The two-step sequence, and why `rehearse.mjs` alone cannot produce it.** That harness

## S2 — Three questions stop being asked _(#118)_

**The specification already exists and is not to be re-derived**:
[`maintainers/registers/gestures.md`](../../registers/gestures.md) § *The 🟢 list*, answered **yes to all
three** on 2026-09-13. The doctrine underneath is
[ADR 0043](../../decisions/0043-graduated-autonomy-and-plain-language.md): a gesture may go quieter only
because **every change the brain writes is committed to the owner's own history as it happens**, so
anything done unasked is one undo away.

- [ ] **S2.1 — a note the engine cannot read has its header put straight** (`engine-skills/lint/SKILL.md`).
      Tier **🟢**: it acts, and it is **named in the batched tidy-up summary**. It is the one finding that
      costs the owner *answers* rather than tidiness — until it is fixed, that note keeps answering
      searches with what it said weeks ago.
- [ ] **S2.2 — renaming a universe rebuilds the search, announced** (`.claude/skills/switch/SKILL.md`).
      Tier **🟡**: it says what it is about to do and starts; the owner can stop it. It costs minutes of
      compute and risks no note. **Renaming, not creating or deleting** — see § *What S2.2 turned out to
      be*: the specification's label was wrong about which lifecycle operation it meant, and the row it
      comes from (*"Confirm a full re-index, minutes of compute, no data at risk"*) has only ever had
      one match in that file.
- [ ] **S2.3 — the same when the note-watching was not running** (`engine-skills/rag/SKILL.md`). Same
      shape, same tier.
- [ ] **S2.4 — the two properties that make the above safe, proven rather than assumed.**
  - **Every write these three make lands in the brain's own history.** A gesture that escapes
    auto-commit may not go quiet — that is ADR 0043's price, not a nice-to-have.
  - **The announcement is not a question in disguise**: it says that silence means it proceeds, with no
    question mark and no *"shall I"*. The engine already carries guards of this shape
    (`scripts/lib/autonomy-discipline.test.mjs`, `scripts/lib/signal-announce-discipline.test.mjs`) —
    the work is to route these three through them, not to invent a third net.

> ⚠️ **The boundary that may never move** (ADR 0045, *Guardrails*): a **destructive** gesture keeps its
> **typed** confirmation. Nothing in S2 is destructive, and nothing in S2 makes deletion easier to reach.

## 📜 History, and the durable half

### What S2.2 turned out to be — measured, 2026-09-13

The specification says *"re-index after a universe is **created or deleted**"* — in the register's
🟢 list, and again in the public wording of [#118](https://github.com/tpierrain/kenjaku/issues/118).
**Read against the code, neither half of that label exists**, and the third operation nobody named is
the one that matches:

- **Creating** a universe re-indexes **nothing**, and cannot: `set-active-universe.mjs create`
  registers a name and re-points the pointer. A universe one second old holds no notes, so there is
  nothing to re-encode and no wait to authorise.
- **Deleting** one does re-index — inside `delete-universe.mjs`, **after** the owner has retyped the
  name, in their own terminal, on a script that refuses to run without one. That gesture is
  **destructive**, so ADR 0045's guardrail freezes it exactly where it is. Its row in the register is
  a separate `keep`.
- **Renaming** is the one left, and it is the one the register's row actually describes: *"Confirm a
  full re-index (minutes of compute, no data at risk)"*. `rename-universe.mjs` re-embeds every note
  of the universe, `switch/SKILL.md` runs a `--preflight` that says what it costs and then **asks
  them to confirm**, and the rename itself loses nothing (renaming back undoes it). Reversible,
  certain, minutes of compute → 🟡 by the gate, which is precisely what the row proposed and the
  owner accepted.

**So the accepted decision stands and only its label was wrong.** The gesture put to him — *stop
making me authorise a wait that risks no note* — is the one being implemented; it simply lives in the
rename flow. **#118's body says otherwise and is public**: the correction rides in the evidence
comment when S4.3 closes it, rather than in a silent edit of his issue.

### Which brain the rehearsal runs on — settled, and it needed nobody

_(2026-09-13.)_ The machine carries four brains, and the rehearsal **only ever reads an original**
(the copy is taken without its `.git`, every write lands under `--work`). So S1.5 needs no decision:

- **`~/autre-brain` — v3.5.0. The one.** It is the exact version issue #115 reproduces on, and the
  further back a brain sits, the more the release has to catch up.
- `~/legacy-brain` (v3.4.0) — a second old one, worth a pass if the first shows anything odd.
- `~/mind-palace` (v5.3.0) — recent, so it exercises the *other* half: a brain that must NOT change
  behaviour. Cheap, and it is the control.

⚠️ The issue's shape is a **two-step** sequence, and one rehearsal run is one update. The contamination
is produced by the first (old engine → new release) and only *shows* at the second, so the trial is
run twice, the second time against the copy the first left behind.

### Both locales, and why this release escapes them

Measured when this plan was written, so nobody re-derives it: the staged skills have **no French
twins** (`templates/fr/engine-skills/` does not exist), and `switch` has no twin either
(`templates/fr/.claude/skills/` carries coach, import, improve, prepare-1-1, sync, sync-sources,
update-engine). **Every file S2 touches is English-only**, so this release never meets the
`templates/fr/**` clause, whose contradiction with green-only commits is still open in
[`clear-the-tracker-action.md`](clear-the-tracker-action.md) § *History*. If a step ever grows a French
twin, that clause wakes up: the French wording is **his**.

### Why these three ride together, when only two are features

**#115 and #118 are one release's worth of the same promise**: the brain stops being wrong *about the
person*. One stops blaming them for an edit they never made; the other stops asking them to authorise
things that were never really decisions. They fit on one tin, in one sentence.

**#113 is not on the tin at all.** It changes nothing anyone will see, and that is the honest way to
present it. It rides here for a reason of timing the owner named himself: the measurement is being run
anyway at the release tail, and paying an old public debt costs an extra pass rather than an extra day.
