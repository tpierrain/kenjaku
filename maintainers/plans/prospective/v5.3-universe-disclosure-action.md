## Design — the six items, and what each one actually touches

### Step 1 — #68: `/switch` names the residue _(ship first, alone)_

**What today does.** `runSwitchCli` (`scripts/lib/universes.mjs`) re-points the pointer and returns a
one-line message, to which `nativeConnectorsReminder` already appends one disclosure: *the live
connectors did not follow this switch*. Retrieval is re-scoped server-side from the next search.

**The gap.** Nothing says the **conversation window** still holds everything read from the sphere just
left. So the answer *looks* scoped and is not — the issue's own framing, and it is a trust defect
rather than a token one.

- [x] **`conversationResidueReminder`, beside `nativeConnectorsReminder` in `universes.mjs`**, appended
      by the core so the skill only relays it (ADR 0009).
  - [x] 🔀 **The emission condition changed under the test, and the change is the interesting part.**
        The issue says *always*; the design says **`from !== to` AND `from !== default`**. Leaving the
        cross-cutting scope **widens** what is reachable — default notes stay in scope after the switch
        (ADR 0034) — so what the window holds is still answerable and there is nothing unscoped to
        disclose. It is the **exact mirror of `nativeConnectorsReminder`**, which warns on
        `default → named` and stays silent on `named → default`, because the two disclose two different
        scopes. That asymmetry is now asserted in both directions rather than commented.
  - [x] **Both switch paths, not just the fast one.** `create` is a switch (`git switch -c` ergonomics),
        so landing on an existing universe from a named one leaves the same residue. An existing
        exact-message test caught the change, which is what an exact-message test is for; its expectation
        was updated **without loosening it to a `match`**.
  - [x] Named-universe fixtures throughout, never `default` alone — the blind-spot lesson, applied.
  - [x] Wording per ADR 0043: the engine is the explicit actor (*"I still have…"*), plain words.
- [x] **The `/clear` suggestion is prose in the skill, conditional, and it stays advice**, with the
      legitimate keep-it case named, and **filing the unsaved part offered first**.
  - [x] 🛡️ **And the prose has a guard**, `scripts/lib/switch-disclosure-discipline.test.mjs`: four
        assertions, **verified to go red against a deliberately broken copy** of the skill. It pins the
        half a pure function cannot — that the agent is told what to *do* about the residue (search
        again, or say where it knows a fact from), not merely to relay a sentence at the owner.
- [x] ⛔ **The issue's item 2 (run the save-point check on the universe being left) is DEFERRED, with
      its reason.** In a brain there is no repo plan to check against, so "is there state that lives
      only in this conversation?" is a judgement, not a deterministic verdict — and shipping it as a
      deterministic-looking check would be the very thing ADR 0009 pushes back on. What ships instead
      is the skill instructing the agent to offer to file a note first. **Revisit if the field shows
      unsaved state actually being lost at a switch.**

### Step 2 — #82: the gate becomes something the core SAYS

**What today does.** `/sync` step 5 announces the active universe **only when the pull changed it**.
`set-active-universe.mjs current` prints a bare slug and nothing about the gate.

**The gap the issue names**, and it is right: the condition should be *"this brain has more than one
universe"*, not *"the universe changed"*. A brain with three universes gets a full git report and not
a word about the one piece of state a sync can carry.

- [x] 🔎 **A premise of the issue was off, and fixing it is what made this step cheap.** The issue
      says to expose *"the same marker"* the core already prints. **That marker did not exist**:
      `.claude/skills/switch/SKILL.md` instructed the agent to look for the literal words `BELOW the
      disclosure gate` / `PAST the disclosure gate` *"printed with the offer"*, and nothing printed
      them — `profileCaptureOffer` conveys the same decision in prose. So the skill sent the agent
      looking for a string that was never there, and the only thing left to it was counting universes,
      which that very paragraph forbids. **The fix made the documentation true** instead of working
      around it: the words the skill promised are now the words a command prints.
- [x] **A `gate` subcommand** on the switch CLI, printing exactly `BELOW the disclosure gate` /
      `PAST the disclosure gate`, and `/switch` now names the command that answers.
  - [x] **It reads the REGISTRY, not the pointer** — asserted. A pointer aimed at an unregistered
        universe is a damaged brain (which `healActiveUniversePointer` repairs), not a multiverse, and
        deciding from it would tell a single-universe owner about machinery they never created.
  - [x] ⚠️ **`current`'s output stays ONE bare slug, and a test pins it twice** — once on the value,
        once on the shape. `/sync` reads it on both sides of the rebase and compares, so a second line
        of output there would have broken a caller in silence. **That constraint is why the gate is a
        new verb** rather than extra output on an existing one.
- [x] **`/sync` step 5 relays the gate instead of comparing**: past the gate it always names the
      active universe, with both wordings (changed / unchanged); below the gate it stays silent, and
      the prose now says that silence is legitimate **only** there (ADR 0034 intact).
  - [x] 🛡️ **Guarded on both locales** in `sync-skill-discipline.test.mjs`, and **verified red against
        the old condition**. The two gate markers stay in **English inside the French skill** on
        purpose: they are the core's literal output, and a translated marker is one that never matches
        what the command prints.
- [x] **Both halves of the French pair in the same commit**, per the standing practice.

### Step 3 — #72: a write into another sphere than the pointer is noticed

**The measured cost, and it is the reason this group is not polish.** Ten hours, fourteen notes filed
correctly under one universe while retrieval served another, and **eight meeting preparations built on
a corpus amputated of its most relevant half**. The writes were right and the pointer was right; they
disagreed in silence, and the owner noticed by chance.

**Why the model cannot be the net** (the issue's own reasoning, and it is sound): filing is correct
*because* the assistant reads the content, and that correctness is what hides the divergence. A note in
the right folder produces no symptom. Critical, repeatable, mechanical → deterministic (ADR 0009).

- [x] **The seam already exists and must be reused, not re-derived.**
      `scripts/lib/vault-write-guard.mjs` runs on `PreToolUse(Write|Edit)` and its `guardedNotePath`
      already turns a tool call into a vault-relative path. **That path derivation becomes the shared
      vault-path codec** the blind-spot plan's M2 asks for — built here, where a second consumer finally
      justifies it, rather than as a speculative refactor.
  - [x] The codec owns one question in one place: *given a vault-relative path, which universe segment
        is it under?* — answering `default` for the root, because an **absent** prefix is what default
        means (ADR 0034). Both existing callers route through it; the M1 twins are the safety net.
- [x] **A new pure module `scripts/lib/universe-drift.mjs`**: given the written path, the pointer, the
      registry and what was already said this session, it returns the notice or `null`.
  - [x] **Silent unless the path's segment is a REGISTERED universe and differs from the pointer.** An
        unregistered folder is not a universe, and guessing would make every stray directory a warning.
  - [x] **Once per session per slug.** Fourteen identical warnings is noise, and noise is how a net
        stops being read. Keyed by the hook's `session_id` + slug, in `.cache/` (per-machine,
        gitignored, fail-soft: an unreadable marker reads as "nothing said yet", never as a crash).
        🔑 **And a correction already announced is still APPLIED** — only the telling is once, which
        is the distinction eight meeting preparations turn on.
  - [x] **Never blocks, ever.** Filing a note into another sphere is a legitimate gesture; what is
        never legitimate is doing it *without knowing*. And ⛔ **auto-switching on write is rejected**,
        for the issue's reason: it would guess intent from one file, and a wrong auto-switch moves the
        scope under the owner without asking — worse than a stale pointer.
  - [x] Named-universe fixtures on **both** sides (pointer named / path named), because `default` is
        the one value where the prefix is absent and therefore cannot reveal this bug.
- [x] ✅ **The channel question is SETTLED, and not by picking one of its two options — by step 4's
      answer removing it** _(2026-09-12)_. Once #66 is also a write-time check, the two steps ask the
      same question of the same event, so the answer is **one `PreToolUse(Write|Edit)` sibling of
      `vault-write-guard.mjs` carrying both notices** → § *Step 4*. That is one extra process per note
      write rather than two, which answers the latency objection that made this a question; and
      `PreToolUse` is what lets #66 prevent a wrong spelling instead of reporting one.
  - **What the two options were, kept because the trade-off is reusable**: (a) fold the notice into the
    existing refusing guard — no new process, but a hook whose job is *refusing* gains a non-refusing
    one; (b) a `PostToolUse` sibling — one hook one job, at the cost of another process on every write.
    **The resolution was neither**: a third consumer appeared and made a sibling worth its own process.

### Step 4 — #66: the facts that must survive a `/clear`

**The real failure, and it is worth keeping.** A client's name — `cortAIx` — spelled *Cortex* in a
transcript, *Cortaix* by one colleague, *Cortex/Thales* by another. The owner had resolved it once and
the vault recorded it, in a person note. A new note drafted from a Slack DM brought the wrong spelling
straight back, because nothing carried the resolved name into the session that needed it.

**Why the existing surfaces miss it** (verified in the code, not taken on trust):
`renderUniverseSynthesis` rides every session start, `/clear` included, and is deliberately the
identity line plus a pointer — never the body. `renderUniverseDigest` does read the body, but only
through the headings in its `SECTIONS` table, and it only lives in the session where the switch
happened. So a hand-added section is dropped **even at switch time**, and a fact that rides only the
digest dies at the next `/clear`.

### ✅ ANSWERED 2026-09-12 — check it at the WRITE, and steps 3 and 4 become ONE guard

**His call, put to him with both costs and taken on the recommendation:** *check at the moment the
brain writes*, not *print the facts at every session start*. So **nothing is added to the session-start
block** and ADR 0035 §2 stands untouched. **Do not re-open this**, and in particular do not "simplify"
step 4 later by appending a line to the synthesis: that is the option he declined, and the reason it
was declined is a transcript that reached a third party.

- **The consequence is a simplification, and it also settles step 3's open channel question.** Both
  steps ask the same thing of the same event — *what does this write say about the sphere it lands
  in?* — so they are **one hook**, not two:
  - [x] **One `PreToolUse(Write|Edit)` sibling of `vault-write-guard.mjs`**, sharing its
        `guardedNotePath` derivation (which is the vault-path codec of § *M2*). **Before** the bytes
        land, which is the whole advantage for #66: a wrong spelling is prevented, not reported.
  - [x] It carries **both** notices: the **universe drift** of #72 (this path's segment is not the
        pointer) and the **declared-spelling mismatch** of #66. **Never blocks** either way, and
        fail-open on anything it cannot judge — same discipline as the guard beside it.
  - [x] **One extra process per note write, not two**, which is the answer to the latency objection
        that made the channel a question in the first place.
  - [x] ⚠️ **`guardDecision`'s REFUSAL stays in `vault-write-guard.mjs` alone**, and a measurement
        now backs it: with both hooks answering one call, a refusal beats a concurrent rewrite, so the
        corrector cannot disarm the guard next door (ADR 0044). One hook refuses
        unindexable notes; this one only ever speaks. Mixing a refusal and an advisory in one verdict
        is how a warning eventually starts blocking.
- [x] **ANSWERED AND BUILT — which words does it check?**
      The profile's `## Always true here` entries are prose, so the guard needs something it can
      match. **Recommendation: the section declares the canonical spelling and the wrong ones it has
      actually seen** (the discipline is already *only entries that have caused an error*), so the
      guard looks for the **wrong** spellings — a closed, owner-written list — rather than trying to
      infer proper names out of free text. Matching what is known-wrong is decidable; recognising
      proper names is not.

#### ✅ HIS REFINEMENT, 2026-09-12 — it CORRECTS and reports afterwards; it never asks

_(« quand on travaille avec un second brain, on l'envoie travailler sur des préparations de meetings,
et on ne veut pas qu'il reste bloqué … par défaut il corrige et on n'est pas prompté. »)_

**The first design was wrong in its tier, not in its mechanism.** It stopped and told the owner, which
is fine at a keyboard and useless in the case this feature is *for*: a brain sent off to prepare eight
meetings. A question waiting for an answer in the middle of that is a halt, and a halt is worse than a
misspelling. **So the tier is 🟡, not 🔴** — ADR 0043's *announce-then-act*, batched, undoable — and
this is a confirmation of accepted doctrine rather than a new idea: the guarantee that makes 🟡 safe is
that **everything the brain writes is auto-committed**, so nothing it changes is ever lost — the
previous state stays in git whatever the correction did. _(What the undo gesture itself is changed with
the 2026-09-12 measurement: it is an edit back, not a `git revert` — see the undo sub-step below.)_

- [x] **It corrects, deterministically, without asking.** A declared wrong spelling is replaced by the
      declared canonical one. No question, no pause, no prompt.
  - [x] ⚠️ **The correction is made by the CODE, not by instructing the model to rewrite.** A hook that
        hands back *"please write it correctly"* depends on compliance, and the whole point of ADR 0009
        is that the mechanical part must not.
  - [x] 🔬 **MEASURED FIRST, 2026-09-12, and it changed the design** — the step's own first gesture,
        run before a line of it was written. Two probe hooks on one `PostToolUse` event, Claude Code
        2.1.220 / macOS: **they run CONCURRENTLY** (their 700 ms busy phases overlapped, the observer
        ended still seeing the uncorrected bytes), **in both shapes** (one `matcher` group or two), and
        **declaration order decided nothing** — the corrector was declared first and started second,
        twice. So *"order the lines in `settings.json.template`"* was never an available lever, and the
        test that was to pin that order would have pinned a coincidence. **Both sub-steps it supported
        are struck.**
  - [x] ✅ **So the correction moves to `PreToolUse(Write|Edit)` and rewrites the tool INPUT**, which
        the same probes proved the host honours: `hookSpecificOutput.updatedInput` made the note land
        already corrected, and the `PostToolUse` seat — `auto-commit`'s own — never saw anything else.
        **One write, one commit, nothing to order.** Two measured properties the design leans on:
        it works **without** claiming `permissionDecision: "allow"` (correcting must not grant, or the
        guard would auto-approve every write it touches, including ones the owner's rules would stop),
        and it works on **`Edit`** as well as `Write` (the rewrite lands on `new_string`).
  - [x] 🎯 **What gets pinned by a test is therefore NOT an order**: that the guard emits
        `updatedInput` and **never** a permission decision, and that it leaves the input untouched when
        it has nothing to correct. Both are assertions on a pure module.
  - 📐 **The full sequencing, the measurement and the diagram live in the ADR**, not here:
        [`0044`](../../decisions/0044-narrowing-a-scope-discloses-what-stayed-wide.md)
        § *How a write-time correction sequences with indexing and committing*. **Do not restate it.**
        Its load-bearing fact is now simply that **the file is written once**: the race was not solved,
        it was deleted. The `sha256`-diffing index stays the backstop for any correction that ever has
        to land after the bytes.
- [x] **It says so when it hands the result back, once, batched.** *"I corrected the spelling myself to
      follow your rule for this sphere. If that was wrong, say so and I will undo it."*
  - [x] **Reuse `remote-arrivals.mjs`'s shape rather than inventing one** — it is the same problem
        already solved here: a trace on disk, a directive addressed to **Claude** (never prose written
        at the human, or a hook writes English into a French conversation in identical words every
        time), and a **stamp so it is said once**, never at every message.
  - [x] **Batched across the whole run**: eight meeting preparations must produce **one** closing
        sentence, not eight interruptions. That is the same *warn once, not per file* rule #72 asks
        for, and for the same reason: noise is how a net stops being read.
  - [x] ⛔ 🛟 **The extra net is NOT built, and the measurement is why** _(2026-09-12)_. It was scoped
        when the correction was going to land AFTER the write, where the corrector has no way to reach
        the model at all — hence a `Stop` hook or the next-prompt channel. Correcting the tool INPUT
        moved the directive **in-band**: the model is told at the moment of the write, in the same
        payload, before it has finished the gesture. A second announcement at the next prompt cannot
        tell *said* from *not said* — no hook can read the reply — so it would re-announce every
        correction that was already relayed, which is the exact noise the rest of this step spends its
        design on avoiding. **Revisit the day the field shows a correction going by in silence**; the
        record is in `.cache/write-notices.json` either way.
- [x] **The undo has to be a real gesture — and the measurement above changed what that gesture IS.**
      With the correction applied to the tool input, the note is written **once**: there is no
      correction commit to revert, only the note's own commit, and reverting that would delete the
      note. So *"say so and I will undo"* means **the brain edits the passage back**, and the skill
      must say so.
  - [x] 🔁 ⚠️ **Which creates the one failure this design can produce on its own: the guard corrects
        the undo.** The owner says no, the brain writes the refused spelling, the guard replaces it
        again, and the owner's word loses to a hook — the exact inversion a 🟡 tier is supposed to
        prevent. **A one-shot bypass is therefore part of the deliverable, not a refinement**: the
        undo has to be able to say *"this write is the correction being reversed, leave it alone"*.
      Design it with the trace that already carries the report, and cover it with a test that fails if
      a corrected passage cannot be put back.
- [x] 🔀 **And the two halves of this guard now sit at DIFFERENT tiers, deliberately.** The spelling
      half **corrects** (🟡): there is a declared right answer, so acting is safe. The universe-drift
      half of #72 only **reports** (also 🟡, but report-only): auto-switching the pointer from one
      file's location was explicitly rejected — it guesses intent, and a wrong auto-switch moves the
      scope under the owner. **A typo with a declared answer is not an intent question**, and that is
      the line between the two.

### The trade-off as it was put to him — kept, because it is the reasoning any future "just inject it" must answer

**Found 2026-09-12, before writing any code, by reading what the invariant is FOR.** #66 proposes to
append the facts to `renderUniverseSynthesis`, and notes correctly that the synthesis is *"deliberately
never the note's body"*. What the issue does not name is **why** — and the why is not verbosity:

> ADR 0035 §2 / §6bis: a `SessionStart` hook's `additionalContext` is **echoed verbatim by the CLI**,
> so every line injected is printed **before the owner has typed a word** — in every screenshot,
> screen share and transcript. A profile passage tagged *"🔒 CONFIDENTIEL, ne jamais sortir du vault"*
> rode every session start, **including one that reached a third party** (finding F1, 2026-08-02).
> *"Inject without showing" does not exist.* Two roads led out; the body was taken out of the block.

**So the content #66 wants carried is the worst possible content to carry**: its own worked example is
a **client's identity** (`cortAIx`, Thales' AI accelerator). Appending it to the synthesis prints a
client relationship on screen at the top of every conversation. The cap does not help — the cap was
always about volume, and F1 was never about volume.

- **(a) What the issue said: append it to the session-start block.** Cheap (a heading in the
  `SECTIONS` table, a capped line, half a day with tests). **Cost: it re-opens F1** for exactly the
  class of fact most likely to be sensitive, and the F1 incident had a third party in it. **DECLINED.**
- **(b) ⭐ Catch it at the WRITE instead of hoping ambient context prevents it.** **TAKEN.** Nothing is
  printed at session start, so the leak stays closed, and it catches the failure *at the moment it
  happens* — which is what actually went wrong: a note was drafted from a Slack DM and the wrong
  spelling came straight back in. Ambient context only ever makes that *less likely*; a guard makes it
  *visible*. It is also ADR 0009's own test — critical, repeatable, mechanical.
- **Why it was his and not a session's**: (a) is what he asked for in his own issue, and (b) declines
  to do that on the strength of a decision he took six weeks earlier. Either was defensible; only the
  owner could say whether the convenience was worth re-opening a surface that leaked once.
- [x] **Whatever the shape, these hold:**
  - [x] **`## Always true here`, not the issue's alternative `## Proper names`** — the heading shapes
        what gets written into it: *proper names* invites a glossary, and a glossary is the second
        `CLAUDE.md` this feature exists to prevent.
  - [x] **Only entries that have ALREADY caused an error**, never a preventive glossary, documented in
        `/switch`'s capture flow — and the prose has a guard of its own, verified red against a
        softened copy.
  - [x] **The value beyond the bug**: it removes the incentive to put a per-sphere fact into the global
        `CLAUDE.md`, which is the leak universes exist to prevent and the owner's current workaround.
  - [x] A named-universe fixture **plus** the `default` twin: the root profile carries **no**
        `universe:` key by design, so both paths through `universeProfilePath` must be exercised.
  - [x] **ADR 0035 amended in place** — new **§6ter**, 2026-09-12: §2 is unchanged and now affordable,
        because something other than the ambient channel is allowed to read the note. **Not a new ADR.**

### Step 5 — #100: an available update becomes an offer that comes back

**What already works and must not be rebuilt** (the issue is explicit, and the code agrees): the daily
detached probe, the four distinct states in `upstream-cache.mjs` — available / up to date / *could not

#### What step 5 decided, that the items above did not say

- 🧱 **THE FLOOR IS THE WHOLE DESIGN, and it is written by the hook, not by the answer.** The stamp
  goes down the moment the offer is SPOKEN. Everything downstream — Claude asking, the owner
  answering, the command recording it — is then an *improvement* on "ask again tomorrow" rather than
  a load-bearing part. That single choice is what makes every failure mode harmless: an unanswered
  question, a refused permission dialog, a read-only disk, a conversation abandoned mid-sentence.
  There is no path through this feature that nags.
- 🗣️ **The answer comes back through a COMMAND** (`scripts/update-offer-answer.mjs`), because a hook
  has exited long before the question is on screen and a conversation cannot call a function — the
  same shape, and the same reason, as `adopt-engine-file.mjs`.
- 🔓 **One allowlist entry, and it is the only one this release adds.** A permission dialog is
  normally healthy; here it would land immediately after someone chose *No thanks*, naming a script
  they have never heard of, to record that they want to be left alone. A fresh brain gets the entry at
  install. **An existing brain does not get it automatically** — the reconciler additively merges
  *hooks*, never permissions — so until its owner adopts the new `.claude/settings.json` through the
  ordinary merge regime, the command still asks. Survivable by construction: declining costs the
  ladder, never the brain.
- 📝 **The cached verdict now carries the offered release's own words**, which reverses a rule
  `upstream-cache.mjs` stated explicitly. It was right for its one reader (the session line quotes no
  prose); the offer is a second reader that must quote verbatim and may not touch the network in
  front of a prompt. **One release, never the backlog**, and the test that asserted the old rule now
  states the reversal and why.
- ✂️ **A long `What you get` is CUT, never summarised**, and the cut points at `/update-engine --check`
  for the rest. A summary would be the machinery choosing which half of a release an owner gets to
  weigh.

### Step 6 — #101: say how long it takes, and get the figure from a measurement

**The defect is which number the owner reads.** The consent message describes everything the update
does and never says it is ordinarily over in about a minute. The **only** duration in it today is the
scary one — *"a few minutes"*, the reindex case. So a non-technical owner reads a long, careful
description of code being replaced on their machine and cannot tell whether yes costs them a minute or
an afternoon. **An unknown cost is postponed**, and postponing is what leaves a fleet several releases
behind.

- [x] 📏 **MEASURED — 9 s ordinary, 24 s with a re-index** _(2026-09-12)_. If it is not "under a
      minute", the sentence states what it really is: the point is that the owner knows the cost, not
      that the cost is flattering.
      - ⚠️ **NOT by the §10ter rehearsal, and that is a correction worth keeping**: the rehearsal
        **stubs `npm install` and the re-index**, so it can never time an update — its whole run took
        2.8 s. The figure came from a second trial the plan had not foreseen: a real, un-stubbed
        `update-engine` on a copy of a brain installed at **v3.4.0** (30 notes), run twice — once
        catching up (the re-index case, **24 s**), then again on the same version (the ordinary case,
        **9 s**).
      - **The sentence still says "about a minute", deliberately on the slow side.** That brain's
        dependencies were already installed, and a cold `npm install` on a slow line is where the
        rest of the minute goes. A duration an owner beats is a promise kept.
- [x] **One sentence, two surfaces, identical wording — so it lives in ONE place and is QUOTED.** The

      _(`update-duration.mjs` + `update-duration-discipline.test.mjs`. **The French twin is a SECOND

## 📜 History — what this plan has learned

_Durable by construction: everything here is finished, or is a lesson. Nothing here expires, so
nothing here needs re-reading at a resume._

### A FOURTH door onto an engine script existed, and no guard watched it

_(Met on step 5, 2026-09-12, and it nearly shipped.)_ A brain runs an engine script through three
doors the suite already guards: a **wired hook**, a **delivered skill's instructions**, and the
**constitution**. #100 opened a fourth — a **directive the engine INJECTS into the conversation**. A
hook builds a sentence, the harness hands it to Claude, Claude runs the command it names, and no skill
or constitution appears anywhere on that path.

`scripts/update-offer-answer.mjs` was written, unit-tested, **run as a real process by its own
suite**, and declared in no regime of `engine-manifest.json`. Everything was green. The feature would
have reached the fleet with its answer command missing — so every *"no thanks"* would have gone
unrecorded and the offer would have come back the next day for ever, which is exactly the nagging it
exists to prevent.

- **The guard is the fourth sibling**, in `engine-manifest-integrity.test.mjs`, and it asserts on the
  directive's **rendered text** rather than on the module's source: a hook names scripts in its
  comments and imports too, and a guard with false positives is one somebody eventually widens until
  it stops biting. It also fails if the directives stop rendering, so it cannot go blind in silence.
- **The tell, generalised**: a test that *runs* a script proves the script works, never that a brain
  will ever have it. Delivery is a different question from correctness, and only the manifest answers
  it.

### The release was designed before a line of it was written, and two premises did not survive the read

_(2026-09-12, the sitting that opened this plan — autonomous, on his standing grant to prepare v5.3.)_

Reading the code before writing the design changed two items, and both would have been wrong:

- **#82's fix is smaller than the issue thought.** It asks to expose *"the same marker"* the core
  already prints for the disclosure gate. **Nothing prints it.** `.claude/skills/switch/SKILL.md` names
  two literal strings — `BELOW the disclosure gate` / `PAST the disclosure gate` — as *"printed with
  the offer"*, and the offer (`profileCaptureOffer`) conveys that decision in prose instead. So the
  skill has been sending the agent to look for a string that is not there, and the fallback is the
  agent counting universes itself, which the very same paragraph forbids under ADR 0009. Step 2 makes
  the documentation true rather than working around it.
- **#72's guard has a seam waiting for it.** The issue proposes comparing a written path's universe
  segment against the pointer, as if from scratch. `vault-write-guard.mjs` already derives the
  vault-relative path of any `Write`/`Edit`, on the right event, fail-open by design. So the item is a
  pure module plus a reused derivation — and that derivation being wanted **twice** is what finally
  justifies the shared vault-path codec the blind-spot plan has asked for since July.

**The transferable lesson**: an issue written from the outside describes the defect accurately and the
*fix* from memory of the code. Both premises here were about the fix, both were checked in minutes, and
checking them is what turned two steps from "build a mechanism" into "make an existing one honest".

### A branch push runs ONE check, and that is the design rather than a filter misfiring

_(Met on step 1, 2026-09-12, and it looked alarming for a minute.)_ Pushing the branch produced a
green run in which the whole test matrix said **skipped**, which is the exact shape of the silent-net
failure this repo keeps meeting. It is not one: `ci.yml` restricts the expensive jobs to
`pull_request` and to `main`, so **an ordinary branch push costs one short Windows job** — the early
tripwire, which does run the entire harness suite. The 7-check matrix is the merge arbiter and fires
at the PR.

- **So "skipped" on a branch push is correct**, and the branch is genuinely covered on Windows the
  whole time it is being written. That tripwire exists precisely because PRs open at the *end* of a
  release here, and a branch used to reach 50+ commits before Windows ever spoke.
- ⚠️ **What it does mean**: until the PR, nothing has run the suite on **macOS** or on the other Node
  versions. Local green plus the Windows tripwire is a strong net, not the full one.

### Touching a delivered skill makes the fingerprint table stale — and CI names the file

_(Met on step 1, 2026-09-12, and steps 2, 4 and 6 all touch a delivered skill, so it will recur.)_

`.claude/skills/**` is a **merge**-regime path, which means a brain's updater proves a delivered file
is untouched by **recognising its bytes** in `scripts/lib/engine-fingerprints.json`. Change the skill
and those bytes are in no row, so the freshness guard goes red with the one command that fixes it:

```bash
node maintainers/fingerprints/generate-fingerprints.mjs --version v5.3.0
```

- **It is not bookkeeping, it is what keeps an owner's edits.** A missing row leaves the file
  unrecognisable, and the healer then cannot tell *pristine* from *customised* — the whole point of
  the table. `since` is **first-writer-wins**, so the release being cut only ever claims bytes nobody
  shipped before it: regenerating repeatedly during the release is safe and adds one row at most.
- **Do it in the same commit as the skill change**, exactly like the French pairs: a commit that edits
  a delivered skill and leaves the table behind is a red CI for a reason that is not the change.

### The suite's own guards caught two things a careful read did not

_(2026-09-12, step 1.)_ Both were mine, both were caught in seconds, and both are the argument for
running the whole suite rather than the files touched:

- **A link died in the archiving.** Folding the blind-spot plan left `ROADMAP.md` pointing at a path
  that no longer exists; `roadmap-consistency.test.mjs` named it. The roadmap row now describes the
  release plan that absorbed it — a row that *links* rather than restates, per the plans doctrine.
- **A prose guard can be brittle in a way that reads as a missing rule.** Two assertions failed on copy
  that was genuinely there, because **markdown wraps lines** and a literal space does not match a
  newline. The sibling guard beside it had already met this and written it down. Every multi-word
  pattern in the new guard now uses `\s+`, and the fix is a comment pointing at the sibling — the
  cheapest possible way to not learn this a third time.
  - ⚠️ **And on step 2 it bit from the other side, which is the half worth remembering.** Re-flowing
    `/sync`'s announcement put *"followed you from your other computer"* across a newline and turned an
    **existing, correct** guard red. **The fix was to re-flow the prose, not to loosen the assertion**:
    a test someone else wrote to pin a sentence is not mine to widen because my line-wrapping moved.
    The general rule, in both directions: **a literal multi-word pattern over markdown is a latent
    failure**, so write new ones with `\s+` — and when an old one fires, suspect the wrapping before
    suspecting the claim.
