## The bug, in the reporter's words and in the code

A **brand-new conversation**, first message `/switch <universe>`. The confirmation says *"I still have
everything I read in '<previous universe>' in this conversation"* — about a universe this conversation
never touched; it was only the one left active by an earlier session. The reporter also asks whether
this costs tokens.

- **Cause (read 2026-09-26):** `conversationResidueReminder({ from, to })` in
  `scripts/lib/universes.mjs` (~line 247) returns the sentence whenever `from` is a named universe and
  differs from `to`. It knows nothing about the conversation, so it asserts a residue it cannot see.
- **Token cost: none.** Nothing from the previous universe is loaded; the sentence is the whole defect.
  Answer the reporter that way in the issue when it closes.
- **Why the sentence exists** (issue #68): after a switch, what was read earlier in the conversation
  stays in the window while searches move — the answer looks scoped and is not. That disclosure is
  right **when something was read**, and must survive the fix.

## Tracking

- [x] **S1 — Design** _(2026-09-26)_
  - [x] S1.1 Find what signal exists, per conversation, that a search returned notes from a universe
        (session id available to the switch? the rag server's own log? a session-scoped marker?).
  - [x] S1.2 Pick one, and write it here with the rejected ones. Candidates:
        **A** — the reminder fires only if this conversation searched while `from` was active
        (needs a per-session record); **B** — no signal is reliable, so the sentence becomes
        conditional and true (*"if I read anything in '<from>' earlier in this conversation…"*);
        **C** — a fresh conversation (no search yet) is detectable at switch time, and the reminder
        is silent then. Prefer the one that makes the statement **true**, not merely softer.
    - **Found (S1.1):** the Bash a skill runs carries `CLAUDE_CODE_SESSION_ID`, equal to the
      `session_id` every hook receives on stdin, and it changes on `/clear` (checked 2026-09-26 on
      this very session). Hooks added to the template reach existing brains on `/update-engine`
      (`hooks-reconcile.mjs`, add-if-absent by script name).
    - **Picked: A, with B as its fallback.** A `PostToolUse` hook on `search_vault|get_document`
      records, per session id, the universe active at the time of each read (`*` for an
      `allUniverses` search) in a gitignored `.cache/` file. The switch reads its own session id:
      - id known **and** the recorder wired in `settings.json` → the reminder names the named
        universes this conversation actually read in, other than the destination; none → silence.
        This also fixes a second lie: after `acme → blue → default` it used to name only `blue`.
      - id missing, or recorder not wired (a brain not yet updated, an older client) → B, a
        conditional sentence that is true without knowing (*"if I read anything in 'acme'…"*).
    - **Rejected:** B alone (true, but still a warning on every switch — the nagging #68 argues
      against); C alone (knows a window is empty, not *which* universes it holds); parsing the
      search output for the notes' universes (the citation format carries paths, not universes).
    - **Cost to reverse:** one hook script, one template entry, one pure function's signature.
