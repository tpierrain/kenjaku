## Tracking

### 1. The six fixes — everything here gates the tag

- [x] **1.1** **DONE** _(2026-09-06, `8c10215`, whole suite 3212 tests / 0 fail)_ —
      `scripts/lib/remote-sync.mjs:148` — **a `git reset --hard ORIG_HEAD` that can delete a
      note the owner just wrote.** A no-op rebase leaves `ORIG_HEAD` untouched, so the ref can name an
      arbitrary older commit, and nothing serialises the tick against `auto-commit.mjs`. **Fix:** capture
      `rev-parse HEAD` before the rebase and use that value for the diff, the authors range and the
      undo; **check the exit status** of the reset and of `rebase --abort`, because
      `remote-arrivals.mjs:195` states as a fact that the pull was undone.
- [x] **1.2** **DONE** _(2026-09-06, `8c10215`)_ — `scripts/lib/remote-sync.mjs:115` — **the freshness probe compares the remote against
      `@{u}`, the ref this tick's own `fetch` already advanced**, so after any failed integration every
      later tick answers *"up-to-date"* (which is total silence) and the brain stays behind for good.
      **Fix:** ask whether the remote commit is already contained in `HEAD`
      (`merge-base --is-ancestor`), which is the question the early return actually means.
- [x] **1.3** **DONE** _(2026-09-06, `8c10215`)_ — `scripts/lib/remote-sync.mjs:116-118` — **`git ls-remote --heads <remote> <branch>`
      glob-matches the ref tail**, so a repo carrying `archive/main` gets several lines and `[0]` reads
      the sibling's SHA. **Fix:** match `refs/heads/<branch>` line by line, as `engine-fetch.mjs:75-83`
      already does. This is 1.1's precondition: it is what makes the no-op rebase reachable.
- [x] **1.4** **DONE** _(2026-09-06, `2203940`, whole suite 3222 tests / 0 fail)_ —
      `scripts/lib/filed-note.mjs:216` — **the `author:` stamp interpolates raw
      `git config user.name` into YAML unquoted**, so a name beginning with a YAML indicator
      (`@tpierrain`, `*thomas`, `- tp`) makes every note that machine files unparseable, and on the
      partner's machine it trips `checkNote` and undoes their whole pull. **Fix:** emit a YAML-safe
      scalar, and pin it with names run through the engine's own parser.
  - 🧱 **The quoting lives in its own module, `lib/yaml-scalar.mjs`**, and quotes ONLY what needs it.
        Quoting every value would have passed every test while rewriting the header of every note in
        every brain. § 2.7 (v5.2) is its second caller by construction.
  - 🚪 **WIDENED to the second door** _(`12c3e35`)_. `dated-note-path.mjs` writes no note: it hands
        back the `author:` LINE and asks for it to be pasted into a header verbatim. Fixing only the
        writer would have been 1.5's mistake told twice in one release. The quoting is on the stamp
        alone — the per-person filename is still slugged from the name itself.
  - ⚖️ **NOT done, and deliberately: no repair sweep over notes already written.** Unlike 1.5, whose
        damage was silent, a broken header is *loudly* refused by the indexer — the owner sees it the
        same day — and it takes a `user.name` starting with a YAML indicator, which would break every
        note that machine files. Building a migration for a case no brain is known to be in, on the eve
        of a tag, buys nothing. **If a real brain turns out to hold such notes, this becomes v5.2 work.**
- [x] **1.5** **DONE** _(2026-09-06, `7e965df`, whole suite 3191 tests / 0 fail)_ — the skill taught
      `sources:` keys quoted while the reader never unquoted, so the ADR 0041 duplicate check silently
      never fired for the notes the skill itself produced.
  - ⚖️ **WIDENED beyond the line this plan first wrote, deliberately.** The plan said "make the
        documented spelling match the writer". That alone would have left **every note already written
        by the skill** unfindable for good, so `noteSources` now unwraps a matching quote pair as well.
        Only a pair wrapping the whole value: a key carries a mail subject, a subject carries an
        apostrophe, and one character eaten there is a source that matches nothing.
  - 🔍 **And the guard that was green throughout is the real lesson.** Four tests pinned the documented
        spelling character for character, and the spelling they pinned was **the quoted one** — they
        asked *"does the doc say this?"*, never *"does what the doc says WORK?"*. Repointed, plus a new
        one with teeth: fill the documented placeholder with a key the brain really composes, read it
        back with the brain's own reader, require the key to come out.
- [x] **1.6** **DONE, and deliberately PARTIAL** _(2026-09-06, `7e965df`)_ — the French em dash this
      branch added in prose is now a colon.
  - 🛑 **What was NOT converted, and why it would have been a defect to convert it.** The other line
        this branch added with an em dash is `## [YYYY-MM-DD] <action> — #canal …`, and it is
        **character-for-character identical in the English twin**: it is the FORMAT of a generated
        note heading, not French prose. Converting it on one side only would have split the two
        locales' output format.
  - 📌 **25 pre-existing em dashes remain in that French file.** Not this release: they predate the
        branch, and rewriting a shipped skill's prose on the eve of a tag buys nothing. → v5.2.

### 2. Not this release — nine findings and one inherited sweep, all real, all deferred to v5.2

Written down so they are not re-discovered. **None of them gates the tag**; they move into a v5.2 plan
the day § 3 is done.

- [ ] **2.1** `remote-sync.mjs:124` — every rebase failure is filed as `reason: "conflict"` with the
      output of `--diff-filter=U`, empty when the failure was not a conflict; an empty list makes
      `remote-arrivals.mjs:190` return null, so **nothing at all reaches the owner**.
- [ ] **2.2** `remote-sync.mjs:130` — `git diff --name-only` octal-escapes non-ASCII paths, so
      `vault/réunion.md` fails `isNote()`, skips the header check, and is shown mangled.
      `repo-status.mjs:26` already carries `stripQuotes`.
- [ ] **2.3** `remote-sync-gate.mjs:154` — reclaiming a stale lock is an unconditional `rmSync` rather
      than a compare-and-delete, so two windows can both emerge holding it.
- [ ] **2.4** `rag/src/lib/remote-sync-interval.ts:27` — `REMOTE_SYNC_INTERVAL` has no upper bound;
      above ~22 days it overflows `setTimeout` and Node rewrites the delay to 1 ms.
- [ ] **2.5** `session-status.mjs:256` — the startup pull writes no arrivals trace, so the
      next-message universe correction promised at 9.4bis/9.6 can never fire.
- [ ] **2.6** `remote-arrivals.mjs:197` — *"keep BOTH contributions"* is issued unfiltered, including
      for `.vault-rag/active-universe` and `authors.json`, where obeying it corrupts them.
- [ ] **2.7** `dated-note-path.mjs:99` — two writers stamp `author:` two different ways (resolved
      through the fusion registry here, raw in `filed-note.mjs`), and the raw fact is destroyed at
      write time.
- [ ] **2.8** `.gitattributes:46` — the narrowed `merge=union` still covers daily and raw-capture
      notes, which carry frontmatter, so duplicated YAML keys stay reachable on today's daily note.
- [ ] **2.9** `CONVENTIONS.md` §3ter — the plans of this release opened with `## 📍 STATE` blocks of 33
      to 334 lines against a *"≤ 20 lines"* rule, dropping its mandatory keys. **This file is the first
      one written to the rule**; the sweep over the others is v5.2's.
- [ ] **2.10** **The dead session-start plumbing** _(inherited from step 9.6.3, the only item still
      open when the parent plan was archived)_: `waitForStartupSync`, `awaitStartupSync`,
      `blockingSleep`, `pullerIsWired`/`pullerWiredIn`, the three timing constants, and then the marker

      **Deliberately not swept on the eve of the tag**: it edits the very sync code this release ships,
      for zero behaviour change. The gate's own ⚠️ blocks already say the question is settled and the
      wait is unused, so nobody wires it back by reading a stale comment.

- [ ] **2.11** _(found while fixing 1.4)_ `filed-note.mjs` also stamps `universe: ${universe}` raw. A
      universe name is a kebab slug by construction (`normalizeUniverseName`), so it is YAML-safe —
      **except** for the handful of slugs a parser reads as a value rather than text: a universe named
      `true`, `false`, `no` or `off` would come back as a boolean. `yamlScalar` already covers it; what
      makes this v5.2 and not 1.4 is that quoting it changes the bytes of every note in a universe, and
      that ripple is not worth taking the day before a tag.
